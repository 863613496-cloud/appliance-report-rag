# 可评测检索原型说明（14 家家电公司 2025 年年报）

> 本轮范围：在已有解析数据上建立**可复现、可核对来源**的混合检索原型，
> 并用 10 道固定题做真实检索测试。
>
> **本轮不做**：Streamlit UI、最终回答生成、最终问答准确率、Git 提交。
>
> **重要边界**：检索命中不等于答案正确。所有题目的最终问答准确率均为
> **未评测**；只有 Q01 有 `logs/midea_verification.md` 的既有原文核验，
> Q02–Q10 没有标准答案。

## 2. 依赖与模型状态

实际使用：

- Python 3.12.9
- `numpy` 2.5.4（矩阵、余弦相似度、向量读写）
- 标准库：`json`、`gzip`、`hashlib`、`re`、`math`、`argparse`、`csv`

**未使用、未安装、未下载**：

- 无 `sentence-transformers`、`transformers`、`torch`
- 无 BGE / 中文 embedding 模型
- 无 `faiss`、`chromadb`、`langchain`
- 无 sklearn / scipy / rank_bm25 / jieba
- 无外部 API、无 `.env` 密钥、未把年报文本发送到外部服务

因此，本原型的“向量检索”必须准确表述为：

> **字符 2–3 gram 哈希 TF-IDF 向量（8,192 维，L2 归一化，余弦相似度）**，
> 不是神经语义嵌入，不是 BGE/FAISS。

它擅长字符/词形重合，不擅长同义改写和跨段推理。Q02 的“空调”与“消费电器”
就是典型例子：字符向量无法把两者判为同一口径。

## 3. 检索架构

### 3.1 文本规范化与 token

`src/index.py`：

- `normalize_text()`：NFKC + 小写；
- `tokenize()`：
  - 中文连续段切 2–3 字 n-gram；
  - ASCII 字母/数字整段保留（含逗号小数、百分号）；
  - 领域短语额外加 `L:` token（营业总收入、营业收入、归母净利润、毛利率、
    境外收入、研发投入、利润分配、每10股、分地区、分产品、单位:元 等）。

### 3.2 BM25

- `k1=1.5`，`b=0.75`；
- 词项 postings 以 `doc_index * 10000 + tf` 打包存储；
- 查询侧做同义扩展（归母净利润、境外收入、境内收入、研发投入、线上销售、
  利润分配、空调业务、产品品类），只增加召回机会，不改变原文。

### 3.3 向量通道

- 哈希字符 n-gram TF-IDF，8,192 维；
- `blake2b-64` 分桶 + ±1 符号，降低桶碰撞偏差；
- L2 归一化后用 numpy 做余弦相似度；
- 不是神经网络，不包含语义模型。

### 3.4 融合与结构意图

- 倒数排名融合 RRF，`k=60`；
- 三路排序：BM25、向量、结构意图；
- 结构意图权重 2.0，只有意图分 ≥2 的文档进入意图通道；
- 结构意图规则（可解释、非模型）：
  - region：分地区、主营业务分地区、境内/境外+营业收入、国内/海外+营业收入、
    境外收入+占比；
  - product：分产品+营业收入/毛利率、主营业务分产品、营业收入构成；
  - rd：研发投入+研发投入合计/占营业收入比例、研发费用+营业收入；
  - dividend：利润分配预案、每10股+现金、现金分红；
  - channel：分销售模式、线上销售+营业收入、线上渠道；
  - financial：主要会计数据+净利润、营业收入+归母净利润+本年比上年、
    营业总收入+归属于母公司、合并利润表+营业总收入；
  - gross_margin：毛利率+营业成本。

`financial` 不会仅因“营业总收入”触发，避免 Q10 被误判为财务指标题。

### 3.5 公司范围与跨公司覆盖

- `detect_companies()`：证券代码、公司简称、常用简称（美的/格力/海尔等），
  以及“全部14家/所有公司”；
- 单公司：只检索该公司；
- 多公司：按公司各取 `per_company` 条，默认 5 家以内取 3 条/家，6 家及以上取 2 条/家；
- **意图覆盖**：多公司且识别到结构意图时，先为每家公司、每个意图各取
  最佳证据页，再用融合排序补足。这样 Q09 的“境外收入 + 研发投入”不会
  被同一意图的结果占满；Q10 的 14 家分地区表也能覆盖。
- 注意：跨公司模式返回条数可能大于 `top_k`（Q10 默认 28 条）；
  `top_k` 是单公司截断参数，跨公司以 `per_company` 为准。
- **财务报表形态覆盖**：当意图含 `financial` 时，每家公司尽量同时返回
  “主要会计数据”和“利润表”两种表形态。规则只看 chunk 正文
  （`financial_form()`），不引用页码或公司名；解决 Q08 海尔 p122 被
  `per_company=3` 截断的问题。

### 3.6 跨页表头上下文

`attach_cross_page_context()` 只在以下条件同时满足时附加片段：

1. 命中结果是 `table`；
2. 页内首个数据行之前没有列头（`analyze_table_header()`，支持折行
   列头累计识别）；
3. 上一页存在，且同公司、同报告年份、同 PDF；
4. 上一页最后一个可信列头位于页面后 30%（`CROSS_PAGE_HEADER_TAIL_RATIO
   = 0.70`）。页面前半段列头通常属于上一页自己的表格，不能作为下一页
   表头；
5. 下一页至少有两行“非正文、非地址、非列头、非纯年份”且每行含 2 个
   以上数字的表格数据行（`CROSS_PAGE_MIN_DATA_ROWS = 2`）。单行附注、
   审计说明和纯正文页不满足。

附加规则：

- 只回看**上一页**，不向前多页扩展；
- 每个片段保留自己的 `页码`，`context_role = "表头来源"`、
  `关联数据页 = 数据页页码`，明确“不是命中页原文”；
- 上下文片段的 `reliable_for_deterministic_answer` 固定为 `False`，
  `上下文关联状态 = "算法判定，待人工核验"`、`上下文关联可靠 = False`；
  源页原值保留在 `源页reliable_for_deterministic_answer`，不混为一谈；
- 表头页已在主结果时不重复附加，只标“主结果”；
- 单题最多 6 条上下文；达到上限时标“未扩展（达到上限）”；
- 证据不足时标“未找到”，并保留 `警告`/`候选表头页`（如有），
  不为了覆盖率强行附加；
- 不跨公司、不跨年份、不跨 PDF 拼接；
- “元数据一致”不等于“语义关联正确”；结构检查只到文本行层面，
  未做单元格坐标或严格列对齐，仍需人工核验。

### 3.7 口径提示

`metric_warnings()` 对相近但不必然等价的指标给出提示：

- 营业总收入 ↔ 营业收入；
- 空调 ↔ 消费电器；
- 研发投入 ↔ 研发费用；
- 境外收入 ↔ 海外/国外/出口/外销；
- 境内收入 ↔ 国内/境内销售；
- 归母净利润 ↔ 归属于母公司股东的净利润等。

提示只说明差异，不自动换算、不替用户选择口径。Q02、Q08、Q09、Q10
均会触发对应提示。

## 4. 结果字段与来源可追溯性

每条检索结果包含：

| 字段 | 说明 |
|---|---|
| `证券代码` / `公司简称` / `报告年份` | 公司标识 |
| `PDF文件名` / `页码` / `块序号` | 原始来源定位 |
| `类型` | `table` / `prose` |
| `章节` | 解析阶段识别的章节，可能为空 |
| `正文` | 原始 chunk 全文，不截断、不改写 |
| `需复核` / `warnings` / `anomalies` | 解析复核标记与明细 |
| `blocking_anomalies` / `blocked` | 是否含阻断性异常 |
| `reliable_for_deterministic_answer` | 是否可作确定性作答依据 |
| `table` | 表格元数据：整页保留、行数、含数字行数、单位行、表头跨行警告 |
| `上下文片段` | 仅表格命中需要时返回；含表头页自己的 `页码`、`context_role`、`关联数据页`、`说明`、`上下文关联状态`、`上下文关联可靠`；固定不可作确定性证据 |
| `跨页表头` | 当前数据页的表头来源：页内已有 / 主结果 / 上下文 / 未找到；附 `关联可靠性`，拒绝时保留 `警告` 与候选表头页 |
| `口径提示` | 题面指标与原文指标名不一致时的显式警告，不自动换算 |
| `source.citation` | 形如“美的集团（000333）2025 年年度报告 p9” |
| `scores` | RRF、BM25、向量、意图分数与排名 |

引用由索引中的原始元数据生成，不接受模型自由生成。`source.citation`
的页码是 **PDF 物理页**，不是印刷页码。

## 5. 表格与异常数据策略

### 5.1 表格

- 解析阶段表格页**整页作为一个 chunk**；
- 索引原样保存 `pdftotext -table` 阅读顺序；
- **未按行切分**，未推断列对齐，未把表格拆成彼此无关的碎片；
- `table_metadata()` 记录行数、含数字行数、单位行、表头跨行警告；
- 已知限制与缓解：跨页表格的列头可能留在上一页。本轮对缺少页内表头的
  表格命中附加同公司/同年/同 PDF 的**上一页**作为表头来源上下文，但要求
  列头在页尾、下一页至少两行数字数据，且下一页没有自己的折行列头；
  保留各自页码，不计入主结果排名。Q07 小熊 p18→p19、Q05 科沃斯
  p105→p106、Q10 小熊/九阳/苏泊尔共 5 条保留并待人工核验；海尔
  p44←p43、格力 p173←p172、p218←p217、小熊 p81←p80 等旧误挂已拒绝。
  上下文语义归属为助手逐页文本比对，不是人工目视核验。本轮进一步用
  PyMuPDF 渲染原始 PDF 页面并做助手视觉检查：4 条唯一关联均获页面证据
  支持，但人工语义确认仍全部待核验（`manual_evidence_review_2025.md`）。
  仍只回看一页，未做单元格坐标/严格列对齐，也未处理表头在更早页或
  整页多表的情况。

### 5.2 异常与 blocked

阻断性异常类型：

- `污染标签`
- `模式间不一致`
- `日期折行截断`

含阻断性异常的文档：

- 仍可被召回；
- `blocked=true`；
- `reliable_for_deterministic_answer=false`；
- 答案生成阶段必须保留警告，不得当作已确认事实。

非阻断异常（如表头跨行、孤立附注行）保留在 `warnings` 中，供人工复核。
本轮没有删除任何异常记录，也没有为了“好看”降低异常计数。

### 5.3 日期修复

日期折行问题继续遵守既有证据规则：

- 只有原始 PDF 文本对象能证明“同处一格”才恢复；
- `-simple` 和列坐标只作旁证；
- 非法日历日期拒绝；
- 证据不足保留原值并标记“待人工核验”。

000651 p143 两处候选拼合值未写回，索引中仍是 `blocked=true`。

## 8. 已知限制

1. **非神经向量**：没有中文 embedding 模型，不能做真正的语义相似度；
   同义改写、跨段推理、口径归并仍会漏召回。
2. **表格跨页**：整页保留解决了“页内表头/数据/单位”关系；本轮加入
   带页尾位置、结构证据和拒绝警告的上一页表头上下文。正例（Q07、
   Q05、Q10 三家）保留但待人工核验；旧误挂已拒绝。仍只回看一页，
   表头在更早页或整页多表时仍需人工判断。
3. **列对齐**：`pdftotext -table` 仍是阅读顺序，未做单元格坐标对齐；
   数字与列名的对应需要人工核对，不能由检索器臆测。
4. **口径差异**：营业总收入/营业收入、境外/海外/国外/出口/外销、
   主营业务收入/营业收入，均需在答案生成阶段显式处理；本轮已输出
   42 条口径提示，但不自动换算、不自动合并。
5. **异常数据**：blocked 页仍可召回，但不可直接作确定性作答；
   本轮未完成人工复核。
6. **无标准答案**：Q02–Q10 没有既有标准答案；本轮只评检索证据，
   不评最终答案。
7. **跨公司返回条数**：Q10 返回 28 条而非 8 条，是覆盖 14 家的设计选择，
   不是 top-k 截断；调用方需理解 `per_company` 与 `top_k` 的区别。
8. **仅 2025 年**：索引只含 2025 年报，未做跨年度检索。
9. **表头启发式**：列头识别依赖文本行特征，不能覆盖所有复杂版面；
   识别失败时保守标“未找到”，不虚构表头。
